# Unit Editor 自动连接设计

日期：2026-06-13
状态：已通过设计讨论，等待实施计划
范围：仅覆盖单位编辑器中的“部件连接方式”环节

## 目标

在玩家已经选择或放置部件之后，让“部件连接方式”尽量由系统自动完成，同时保留玩家手动调整的空间，并在进入“入场姿态”之前要求系统重新评估连接是否合理。

期望玩家体验：

1. 选择或放置躯干、连接肌肉、武器等物理部件。
2. 点击 `自动连接`，让系统生成最合理的拓扑连接。
3. 在画布上检查系统建议的连接结果。
4. 如有需要，可以解绑、拖动、重新连接或翻转侧挂武器。
5. 点击 `评估连接`。
6. 只有连接评估通过后，推荐流程才进入“入场姿态”环节。

## 当前状态

编辑器已经具备这次功能应复用的基础能力：

- 自由画布上的拓扑节点与接口边。
- 基于接口候选的磁吸连接逻辑。
- 手动连接节点的既有行为。
- 右键解绑节点或连接线。
- “布局”和“姿态”两种工具模式。
- 侧挂武器的左右选择与翻侧刃控制。
- `_topology_rule_note()` 作为当前拓扑合法性的权威说明。
- 画布提示与非法连接线的可视化反馈。

目前缺口主要在工作流层：

- 玩家可以手动创建连接，但没有明确的 `自动连接` 指令。
- 玩家不容易判断“连接阶段”是否已经可以进入下一步。
- 推荐流程没有一个独立的连接评估状态来决定是否推进到入场姿态。

## 非目标

这次设计不应简化或绕过当前游戏规则。

- 不移除自由画布编辑。
- 不删除布局模式、右键解绑、姿态模式或侧挂武器控制。
- 不修改拓扑合法性、伤害规则、材质规则、单位保存结构或战斗运行时行为。
- 不自动补齐缺失部件。
- 不自动绑定行动模块。
- 不把行动模块绑定问题作为连接阶段的新增阻断，除非当前拓扑规则本身已经报告该问题。
- 不自动保存，也不在玩家未确认的情况下跳转到下一屏。

## 推荐方案

采用“既有拓扑系统之上的引导自动化层”。

自动化层使用编辑器现有的接口规则生成候选连接。它优先构造最适合新手的合理结构，然后把结果留给玩家继续编辑。玩家始终可以修改系统建议的拓扑，但进入入场姿态之前必须通过一次最新的连接评估。

已排除的替代方案：

- 完全手动连接：表达空间最大，但新玩家最容易卡在技术性最强的一步。
- 完全锁定连接：降低学习成本，但会牺牲合法异形构筑与玩家创造性。
- 独立简化编辑器模式：会复制规则，并且容易和真实游戏规则产生漂移。

## 自动连接规则

连接求解器只处理已经存在的拓扑节点，不创建或删除部件。

优先级顺序：

1. 识别躯干或核心节点作为根结构。
2. 优先使用躯干或核心上的接口作为第一层父接口。
3. 连接肌肉类构件时，优先让 `root_joint` 接到躯干接口或上游 `distal` 接口。
4. 连接终端武器时，优先让 `root_joint` 接到最近的合法上游 `distal` 或躯干接口。
5. 多个合法候选存在时，优先选择接口距离最短的连接。
6. 距离相近时，优先选择尺寸过渡更平滑的连接。
7. 不占用已经被使用的接口。
8. 不把刀刃、枪口、拳面、盾面等功能端作为下游父接口。
9. 保留侧挂武器的方向选择；自动连接只建议连接关系，不替玩家决定战术朝向。
10. 对歧义较大或非法的节点保持未连接，并报告原因，不强行生成错误连接。

求解器必须是确定性的：同一份部件布局应得到同一份建议连接。

## 手动调整

自动连接之后，玩家仍然可以：

- 移动未连接部件。
- 右键解绑节点或连接线。
- 使用手动连接控件。
- 拖动松散部件靠近更合适的接口。
- 翻转侧挂武器方向。
- 在布局工具与姿态工具之间切换。

任何手动连接变更都应把连接评估状态标记为 `stale`。`stale` 表示玩家可以继续编辑，但必须重新点击 `评估连接` 后才能推进推荐流程。

## 连接评估

新增一个连接阶段专用评估模型，和最终保存条件分开。

评估状态：

- `passed`：连接拓扑已经可以进入入场姿态。
- `repairable`：当前拓扑未通过，但自动连接大概率可以修复。
- `blocked`：需要玩家先处理关键问题。
- `stale`：上次评估后拓扑发生过变化，需要重新评估。

评估应复用当前权威拓扑事实：

- 非屏障单位必须有连通拓扑。
- 非屏障单位必须至少有一个躯干或核心。
- 节点必须使用当前支持的部件拓扑，不能继续依赖已废弃的独立关节拓扑。
- 接口必须显式存在并彼此兼容。
- 已连接接口必须在当前容差内重合。
- 每个接口的占用数量必须符合部件限制。
- 尺寸跃迁必须保持在当前允许的等级差内。
- 端点冲突仍然无效。
- 材质连接警告继续以当前规则为准。

在这个阶段，`passed` 只代表“连接拓扑可以进入入场姿态”。之后的阶段仍可能因为内部载荷、行动模块绑定、引擎功率、热量、编队限制或保存规则失败。

## UI 模型

在单位编辑器的组装流程中增加三个控件：

- `自动连接`
- `评估连接`
- `恢复建议`

建议位置：

- 靠近画布工具栏或推荐组装引导区域。
- 仅在当前角色使用自由画布机体编辑时显示。
- 编辑屏障类单位时隐藏，或替换为屏障专用提示。

画布反馈：

- 系统建议的连接在应用前或应用后用独立样式高亮。
- 未解决节点需要高亮。
- 非法连接继续使用已有红色非法边反馈。
- 画布提示栏显示下一步最有用的操作。

推荐文案：

- 通过：`连接评估通过：可以进入入场姿态。`
- 可修复：`部分构件未接入；可尝试自动连接。`
- 阻断：`连接阻断：请先放置躯干或修正接口冲突。`
- 已过期：`连接已改动，请重新评估。`

## 工作流集成

推荐组装路径应把连接视为“物理部件齐备之后、入场姿态之前”的子步骤。

预期流程：

1. 玩家添加或选择物理部件。
2. 引导高亮 `自动连接`。
3. 玩家运行自动连接。
4. 玩家可选择手动调整连接。
5. 玩家运行连接评估。
6. 如果评估通过，引导可以进入入场姿态。
7. 如果评估失败，引导停留在连接环节，并显示最关键的阻断原因。

UI 不应在阻断状态下禁止玩家继续编辑；它只限制推荐流程自动推进到入场姿态。

## 架构

新增一个纯服务或控制器风格的连接推荐单元。

职责划分：

- `UnitEditorAutoConnectionService`
  - 构建候选连接计划。
  - 对候选连接进行排序。
  - 返回确定性的新增连接与节点对齐意图。
  - 基于传入事实返回评估摘要。

- `main.gd`
  - 收集当前拓扑、节点部件、接口和既有编辑器事实。
  - 应用新增边、节点对齐、撤销记录、音效、脏标记和 UI 副作用。
  - 管理画布按钮与标签。
  - 保持当前拓扑合法性与保存行为不变。

这和当前项目已有模式一致：纯服务负责决策，`main.gd` 负责组合与副作用。

## 数据模型

尽量减少运行时和保存结构变化。

可以新增临时编辑器状态：

```gdscript
var editor_connection_evaluation := {
	"state": "stale",
	"note": "",
	"topology_signature": "",
	"repairable_nodes": [],
	"blocked_nodes": [],
}
```

这个状态不需要保存到单位蓝图。已保存蓝图仍然只记录真实拓扑节点、连接边、入场姿态、载荷与模块绑定。

## 失败与恢复

如果自动连接无法连接全部节点：

- 连接安全子集。
- 保留未解决节点为未连接。
- 将评估状态设为 `repairable` 或 `blocked`。
- 优先显示最可操作的原因。

如果自动连接和玩家已有连接发生冲突：

- 保留有效的玩家已有连接。
- 只补齐缺失连接。
- 除非玩家选择 `恢复建议`，否则不删除已有连接。

如果玩家选择 `恢复建议`：

- 记录撤销点。
- 移除和求解器计划冲突的当前连接边。
- 应用确定性的建议连接边。
- 对齐子节点接口。
- 将评估状态标记为 `stale`，直到玩家点击 `评估连接`。

## 测试计划

纯服务探针：

- 躯干加一条肢体时，肢体根接口会自动连接到躯干接口。
- 躯干加肢体加终端武器时，会自动形成躯干到肢体再到武器的链路。
- 现有有效连接会被保留。
- 已占用接口不会被重复使用。
- 终端武器的功能端不会被作为父接口。
- 非法尺寸跃迁会保持未连接。
- 输入顺序变化不会影响确定性输出。
- 评估能按预期返回 `passed`、`repairable`、`blocked`、`stale`。

集成探针：

- `自动连接` 按钮只在自由画布机体单位中出现。
- 自动连接能为新手常见的躯干、肢体、武器布局创建合法边。
- 手动解绑会把评估状态标记为 `stale`。
- 拓扑断开时，`评估连接` 会阻止推荐流程进入入场姿态。
- 自动连接创建合法连通拓扑后，`评估连接` 会通过。
- 自动连接之后，侧挂武器方向提示仍然可用。
- 最终保存合法性仍由当前校验器控制。

## 完整玩家流程

1. 玩家选择或放置躯干、连接肌肉和武器。
2. 引导把当前重点移动到连接环节。
3. 玩家点击 `自动连接`。
4. 编辑器连接安全、明显、符合规则的结构。
5. 如果仍有未解决或风险部件，画布高亮这些部件。
6. 玩家按需要手动调整连接。
7. 玩家点击 `评估连接`。
8. 如果通过，推荐流程进入入场姿态。
9. 如果不通过，编辑器停留在连接环节，并显示最可操作的修复建议。

## 规格自检

- 未完成项检查：没有遗留未确定需求。
- 一致性检查：自动连接是建议式自动化，手动编辑始终可用，评估只限制推荐流程推进。
- 范围检查：这是一个聚焦的单位编辑器工作流功能，可以进入单独实施计划。
- 歧义检查：自动行为不会创建部件、不会绕过拓扑规则、不会在玩家未确认时保存或跳转。
